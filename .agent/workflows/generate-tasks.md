# PRD 기반 작업 목록 작성

## 입력과 산출물

- 입력은 `tasks/prd-[서비스명].md`다. 지정된 PRD가 있으면 해당 문서를 사용한다. 지정이 없고 후보가 한 개면 그 문서를 사용한다. 후보가 여러 개면 대상 PRD를 확인한다.
- 출력은 입력 PRD와 같은 폴더의 `tasks-prd-[서비스명].md`다. 예를 들어 `tasks/prd-숲-현황.md`의 작업 목록은 `tasks/tasks-prd-숲-현황.md`다.
- 실행 범위는 작업 목록 작성이다. 기존 목록을 갱신할 경우 완료된 작업과 검증 근거를 유지하고, 인수 기준이 달라진 작업은 재검증 대상으로 표시한다.

## 절차

1. PRD의 필수 요구사항과 인수 기준을 확인한다. 해당 PRD를 찾을 수 없으면 `/create-prd`로 필요한 문서를 먼저 작성하도록 안내한다.
2. 선행 작업부터 구현과 검증까지, 학생이 한 번의 실행 결과를 확인할 수 있는 크기로 나눈다. 환경 준비나 데이터 읽기처럼 다른 기능의 기반이 되는 작업을 앞에 둔다. 사용자의 정상 흐름과 PRD에서 중요한 예외 흐름을 검증하는 작업을 포함한다.
3. 후속 기능과 미결 사항의 영향을 명시한다. 구현을 막는 미결 사항이 있는 작업에는 필요한 결정을 적고, 독립적으로 진행할 수 있는 작업은 계속 진행할 수 있게 의존성을 명시한다.
4. 모든 필수 요구사항이 최소 한 작업과 검증에 연결되어 있는지 확인한다. 저장 경로와 먼저 실행할 작업 ID를 알린다.

## 작업 목록 구성

문서 상단에 대상 PRD 경로, 프로젝트 실행 방식 또는 참고 항목, 해당 실습의 완료 기준을 적는다. 각 작업은 체크박스 한 개와 아래 세부 항목으로 작성한다.

- [ ] `T-01` 작업 제목
  - 연결 요구사항 · `FR-01`처럼 PRD에 실제로 정의된 ID를 사용한다. 공통 준비 작업은 영향을 받는 요구사항을 연결한다.
  - 선행 작업 · 작업 ID 또는 ‘없음’
  - 구현 범위 · 수행할 동작과 예상 산출물. 프로젝트 구현 파일은 `app/`에 위치한다.
  - 확인 방법 · 실행 명령이나 사람이 따라 할 수 있는 확인 절차
  - 완료 기준 · 예상 화면, 실제로 대조할 수치, 파일 또는 오류 메시지 등 관찰 가능한 결과
  - 검증 결과 · 구현 후 실제 확인 결과 또는 재현 경로를 기록할 자리

원본 데이터가 필요한 작업은 `data/`의 원본을 읽기 전용으로 사용한다. 새 작업의 체크박스는 미완료 상태로 시작한다.
