# 작업 목록 실행과 검증

## 입력과 범위

- 입력은 `tasks/tasks-prd-[서비스명].md`와 목록에 연결된 PRD다. 지정된 목록을 우선 사용한다. 목록이 여러 개이고 대상이 지정되지 않았으면 선택에 필요한 파일명을 안내한다.
- 요청에서 작업 ID나 실행 범위를 지정하면 해당 범위를 따른다. 지정이 없으면 선행 작업이 완료된 첫 미완료 항목 한 개를 실행한다. 선행 작업이 끝나지 않았으면 해당 ID와 이유를 알린다.
- 구현 파일은 `app/`에 둔다. 원본 데이터는 `data/`에서 읽기 전용으로 사용한다. 작업의 진행 상태는 해당 `tasks/` 문서에 기록하고, 검증 근거는 `report/`에 남긴다.

## 절차

1. 작업의 요구사항 ID, 선행 작업, 확인 방법, 완료 기준을 읽는다. 실행 전 변경 예정 경로와 목표를 한 문장으로 알린다. 프로젝트의 기존 코드와 환경 지침을 확인하고 이용 가능한 부분을 재사용한다.
2. 해당 작업을 구현한다. 코드와 입력 데이터의 경로는 팀원 환경에서도 재현할 수 있게 프로젝트 기준 상대 경로로 다룬다. PRD와 작업 목록의 변경이 필요해지면 그 차이와 필요한 결정을 기록한다.
3. 작업 목록의 확인 방법을 실제로 수행한다. 수동 확인이 필요한 조건은 학생이 재현할 수 있는 입력과 화면 경로를 적는다. 오류가 있으면 원인을 확인하고 작업 범위 내에서 수정한 뒤 다시 검증한다.
4. 모든 완료 기준이 확인되면 작업을 `[x]`로 표시한다. 실패했거나 아직 실행할 수 없는 검증이 있으면 `[ ]`를 유지하고 사유와 남은 확인을 적는다. 실제 실행 결과와 예상 결과를 구분한다.
5. `report/verification-[서비스명].md`에 작업 ID, 검증 방법, 기대값, 관찰값과 판정을 남긴다. 같은 작업을 다시 검증할 경우 해당 ID의 최신 결과를 갱신한다.
6. 변경 파일, 검증 결과, 다음에 착수할 수 있는 작업 ID를 학생에게 알린다. 모든 작업이 완료되면 PRD의 핵심 사용자 흐름을 실제 진입점에서 한 번 확인하고 결과를 기록한다.
