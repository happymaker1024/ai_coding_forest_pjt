# 강원 산불 예방 브리핑 프로젝트 실행 프롬프트

Antigravity에서 `산불관리_pjt/`를 열고 Agent 채팅창에 아래 코드 블록을 **한 번에 하나씩** 붙여 넣는다. PRD와 작업 목록이 있는 현재 상태에서는 **3단계 T-01**부터 시작한다. 앞 단계를 다시 실행할 때는 기존 문서의 검토 사항과 완료 기록을 보존한다.

| 단계 | 입력 문서 | 산출물 |
| --- | --- | --- |
| PRD | `docs/SERVICE_PLAN.md` | `tasks/prd-강원-산불-예방-브리핑.md` |
| 작업 목록 | PRD | `tasks/tasks-prd-강원-산불-예방-브리핑.md` |
| 실행 환경과 구현 | 작업 목록, PRD, `docs/개발환경셋팅.md` | 루트의 uv 환경, `app/`의 앱 코드와 테스트 |
| 검증 | 앱, PRD의 인수 기준 | `report/verification-강원-산불-예방-브리핑.md` |

각 구현 프롬프트는 `/process-task-list`로 시작한다. 작업 목록의 완료 기준을 실제로 확인한 뒤 체크박스를 완료로 표시한다. 실행할 수 없는 확인은 미완료로 두고 사유와 확인 절차를 남긴다. 원본 CSV는 모든 단계에서 읽기 전용으로 사용한다.

## 1. 기획서에서 PRD 작성

```text
/create-prd

docs/SERVICE_PLAN.md와 data/산불발생통계(20251110).csv를 확인하고,
tasks/prd-강원-산불-예방-브리핑.md에 PRD를 작성해줘.
사용자, 문제, 첫 구현 범위, FR 기능 요구사항, AC 인수 기준, 후속 범위를 담아줘.
인수 기준에는 기획서의 조회 조건과 원본 CSV에서 확인한 기대값을 명시해줘.
기존 PRD가 있으면 먼저 현재 기획서와 대조해 차이만 알려줘.
이번 단계는 PRD 작성과 검토까지만 진행해줘.
```

## 2. PRD에서 작업 목록 작성

```text
/generate-tasks

tasks/prd-강원-산불-예방-브리핑.md를 읽고,
tasks/tasks-prd-강원-산불-예방-브리핑.md에 작업 목록을 작성해줘.
FR-01~FR-06과 AC-01~AC-08을 모두 연결해줘. 각 작업에 작업 ID,
선행 작업, 구현 범위, 확인 방법, 완료 기준, 검증 결과란을 넣어줘.
기존 작업 목록이 있으면 먼저 PRD와 대조하고, 완료 항목과 검증 기록은 유지해줘.
이번 단계는 작업 목록 작성과 검토까지만 진행해줘.
```

## 3. 작업 목록에 따라 구현

### T-01 로컬 실행 환경과 앱 진입점 준비

```text
/process-task-list

tasks/tasks-prd-강원-산불-예방-브리핑.md의 T-01만 진행해줘.
docs/개발환경셋팅.md에 따라 Windows PowerShell에서 uv와 Python 3.12를 사용해줘.
프로젝트 루트의 기존 pyproject.toml, uv.lock, .venv 및 Python 설정을 먼저 확인해 재사용하고,
필요한 경우에만 루트에서 uv로 초기화해줘. 앱 의존성은 streamlit, pandas, plotly,
테스트 의존성은 pytest로 제한하고, 환경을 동기화한 뒤 버전과 import를 확인해줘.

이 프로젝트의 앱 진입점은 작업 목록에 지정된 app/streamlit_app.py로 사용해줘.
환경 문서의 app/app.py는 예시로 보고, 기능 없이 제목만 표시하는 초기 화면을 만들어줘.
프로젝트 루트에서 uv run streamlit run app/streamlit_app.py로 실행해
브라우저에 ‘강원 산불 예방 브리핑’이 표시되는지 확인해줘.
확인한 실행 명령, 결과, 변경 파일을 기록하고 완료 기준을 충족한 경우에만 T-01을 체크해줘.
```

이 안내서는 개발 환경 문서의 **루트 uv 환경**과 작업 목록의 **`app/streamlit_app.py` 진입점**을 함께 적용한다. 프로젝트 루트에서 실행하는 기준 명령은 `uv run streamlit run app/streamlit_app.py`다. 테스트를 작성한 뒤에는 루트에서 `uv run pytest app/tests -v`로 확인한다.

전국 기록 범위 2022-01-01~2025-09-11을 확인해줘.
별도 테스트 입력으로 파일 누락·디코딩 실패·필수 열 누락을 확인해줘.
각 오류에서 이유를 표시하고 집계를 중단하는지, 검증 전후 원본 CSV 해시가 같은지 기록해줘.

### T-03 기간·시군 필터와 출처 표시

```text
/process-task-list

tasks/tasks-prd-강원-산불-예방-브리핑.md의 T-03만 진행해줘.
기간과 강원 전체·시군 한 곳·서로 다른 두 곳을 선택하게 하고 파일명과 전국 기록 범위를 표시해줘.
첫 화면은 강원 전체 2022~2025년 3~5월 119건인지 확인해줘.
같은 기간 고성·강릉이 각각 3건·9건인지, 2023년 3~5월 양양을 선택했을 때
0건이어도 선택이 유지되는지 확인해줘.
시작 월 또는 연도가 종료 값보다 늦으면 안내가 나오고 새 집계·요약이 생성되지 않는지 확인해줘.
```

### T-04 지역별 총건수와 월별 비교

```text
/process-task-list

```

### T-05 세부원인 비교와 기타 비중

```text
/process-task-list

tasks/tasks-prd-강원-산불-예방-브리핑.md의 T-05만 진행해줘.
원본 세부원인별 건수를 시군별로 표시하고,
‘기타(직접입력)’ 비중은 각 지역 조회 총건수를 분모로 소수점 한 자리까지 표시해줘.
2022~2025년 1~12월 강원은 218건 중 기타 172건(78.9%)인지 확인해줘.
2022~2025년 3~5월 고성의 기타 2건(66.7%)·낙뢰 1건, 강릉의 기타 6건(66.7%),
2023년 3~5월 양양의 0건 비중 표시 ‘–’를 확인해줘.
각 지역에서 원인별 건수 합계와 총건수가 일치하는지 검증해줘.
```

### T-07 회의용 통계 요약과 클립보드 복사

```text

```

### T-08 핵심 흐름과 인수 기준 최종 확인

```text
/process-task-list

tasks/tasks-prd-강원-산불-예방-브리핑.md의 T-08만 진행해줘.
프로젝트 루트에서 uv로 앱을 새로 시작하고 브라우저에서
시군 선택 → 월별·원인별 비교 → 원본 상세 확인 → 요약 복사를 한 흐름으로 검증해줘.

PRD의 AC-01~AC-08에 대해 확인 방법, 기대값, 관찰값, 판정을 대조해
report/verification-강원-산불-예방-브리핑.md에 기록해줘.
정상 흐름뿐 아니라 0건, 역순 기간, CSV 오류도 확인하고 원본 CSV가 보존됐는지 확인해줘.
미검증이나 실패가 있으면 사유와 다음 확인 방법을 적어줘.
모든 인수 기준이 충족된 경우에만 T-08을 완료로 표시해줘.
```

## 확인에 실패했을 때 다시 실행

```text
/process-task-list

현재 작업의 ID [예 T-03]과 실패한 인수 기준 [예 AC-08]을 확인해줘.
관찰한 결과는 [실제로 본 화면 또는 오류 메시지]야.
같은 조건으로 실패를 재현하고, 원인을 확인한 뒤 현재 작업 범위에서 수정해줘.
이전 작업에 영향이 있는지 점검하고 해당 기준을 다시 검증해줘.
해결 여부와 재현 절차를 검증 기록에 갱신하고, 완료 조건을 충족한 경우에만 체크해줘.
```
