## 1. 문제 정의

시군 산불 예방 담당자는 봄철 예방계획을 검토할 때 “우리 시군에서 어느 달에 어떤 원인으로 산불이 기록됐는가?”, “같은 기간 인접 시군과 어떤 차이가 있는가?”에 답할 자료가 필요하다. 아이디어 카드에서는 원본 기록을 지역·월·원인별로 다시 정리하는 일이 부담일 가능성을 제기했다. 기존 도구, 정리 소요 시간, 계획 수립 지연 여부는 담당자 확인이 필요하다.

2026년 10월 20일 연합뉴스는 고성군이 가을철 산불 예방 활동의 일환으로 산림 인접 지역 화목보일러 사용 188가구를 대상으로 방문 점검과 계도 활동을 진행했다고 보도했다. 예방계획에 점검과 홍보 대상이 포함될 수 있음을 보여주는 사례다. 봄철 업무 절차나 통계 정리 부담은 별도 인터뷰에서 확인한다. [연합뉴스 원문](https://www.yna.co.kr/view/AKR20261020078400062)

**서비스 가치**는 담당자가 같은 기간의 발생 기록을 한 화면에서 비교하고, 집계 수치를 원본 행까지 추적한 뒤, 회의에 쓸 통계 요약을 바로 복사할 수 있게 하는 데 있다.

## 2. 사용자 시나리오

고성군 담당자가 봄철 예방회의 자료를 준비한다. 대시보드에서 2022~2025년, 3~5월, 고성·강릉을 선택한다. 월별 그래프에서 두 지역의 기록 건수를 비교하고 원인 표를 확인한다. ‘기타(직접입력)’를 눌러 원문과 조사 상태를 살핀 뒤 조회 조건, 수치, 출처가 포함된 문장을 복사한다. 담당자는 다른 현장 정보와 함께 이 자료를 검토해 예방계획에 반영한다.

| 2022~2025년 3~5월 원본 기록 | 3월 | 4월 | 5월 | 합계 | 기타(직접입력) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 고성 | 2 | 1 | 0 | 3 | 2 |
| 강릉 | 3 | 5 | 1 | 9 | 6 |
| 강원 전체 | 41 | 52 | 26 | 119 | 94 |

고성의 ‘기타(직접입력)’ 2건에는 ‘차량화재’와 ‘조사중’이 각각 기록돼 있다. 원인 표의 동일 분류 아래에 의미가 다른 기록이 섞일 수 있으므로, 담당자가 원문을 확인할 수 있게 한다. 위 표의 0은 해당 조건에서 파일에 남은 기록이 0건임을 뜻한다.

**회의 자료 예시**  
“제공 자료의 2022~2025년 3~5월 기록에서 고성은 3건, 강릉은 9건이다. 고성 3건 중 2건은 3월에 기록됐으며, 원인 항목은 ‘기타(직접입력)’ 2건과 ‘낙뢰’ 1건이다. 기준 파일은 산불발생통계(20251110).csv다.”

## 3. 데이터 확인과 집계 기준

| 항목 | 확인 결과와 표시 기준 |
| --- | --- |
| 입력 파일 | `../data/산불발생통계(20251110).csv` · CP949 · 전국 2,020행 · 18개 열 |
| 시간 범위 | 원본 전국 기록의 최초·최종 발생일은 2022-01-01~2025-09-11이다. 강원 최초·최종 기록은 2022-01-03~2025-08-28이다. 화면에는 파일명과 원본 기록 범위를 표시한다. |
| 자료 출처 | 아이디어 카드가 연결한 공공데이터포털 항목은 산림청 제공 자료로 안내한다. 포털 메타데이터의 기간은 2022년~2024년 9월로, 로컬 CSV의 기록 범위와 다르다. 화면에는 실제 사용한 CSV의 범위를 적용하며, 파일의 공식 배포 이력과 연월별 수록 완전성은 확인이 필요하다. |
| 강원 범위 | `발생장소_시도`를 공백 제거한 뒤 ‘강원’으로 선택한다. `발생장소_시군구`의 공백을 제거하면 강원 기록은 218건, 기록이 있는 시군은 17곳이다. ‘강릉’과 ‘강릉 ’을 통합하면 25건이다. 시군 전체 선택지의 행정구역 목록은 공식 코드표 확보 후 확장한다. |
| 발생 건수 | 집계 단위는 원본 한 행이다. 18개 열이 모두 같은 행은 표본 파일에서 발견되지 않았다. 고유 사건번호가 없어 날짜·시군 일치만으로 여러 행을 합치지 않는다. |
| 원인 | `발생원인_세부원인` 원본값으로 집계한다. 강원 218건 중 ‘기타(직접입력)’는 172건(78.9%)이다. `발생원인_기타`는 상세 화면에 원문으로 표시하고, `발생원인_구분`은 강원 기록에서 24건이 비어 있고 코드 의미 확인이 필요해 원본 확인에만 제공한다. |
| 피해면적 | `피해면적_합계`는 원본 확인이 가능한 항목이다. 단위가 확인되면 별도 지표로 추가한다. |
| 빈 결과 | 조회 조건에 일치하는 행이 없으면 ‘선택 조건의 기록 0건’으로 표시한다. 2025년은 파일상 9월까지 일부 기록이 있으므로 전년도 전체와 증감률을 계산하는 뷰는 후속으로 둔다. |

## 4. 최소 기능 제품과 화면 구성

업무 흐름은 **기간·시군 선택 → 월별·원인별 비교 → 원본 확인 → 회의 자료 복사**로 구성한다. 시군 선택은 두 곳까지 지원하고, 기간은 선택 가능한 연도와 월 범위로 구성한다. 첫 화면의 월 범위 3~5월은 봄철 실습 시나리오 기준이다.

| 우선순위 | 화면·기능 | 동작 및 완료 조건 |
| --- | --- | --- |
| 필수 | 대시보드 상단 · 조회 조건 | 첫 접속에는 강원 전체를 표시한다. 연도, 월 범위, 비교 시군을 바꾸면 요약과 모든 집계가 같은 조건으로 갱신된다. 파일명과 기록 범위를 상단에 표시한다. |
| 필수 | 대시보드 본문 · 월별 비교 | 지역별 총건수와 월별 막대그래프를 제공한다. 두 시군은 같은 축을 사용하고, 정확한 수치를 읽을 수 있는 표도 제공한다. |
| 필수 | 대시보드 본문 · 세부원인 비교 | 원본 세부원인별 건수를 시군별 열로 나란히 제공한다. 시군별 분모는 해당 조회 조건의 총건수이고, ‘기타(직접입력)’ 비중을 함께 표시한다. |
| 필수 | 원본 기록 보기 | 월 또는 원인을 선택하면 해당 기록의 발생일, 시군, 세부원인, 기타 원문을 표로 보여준다. 상세 행 수와 선택한 집계 건수가 일치한다. |
| 필수 | 회의 자료용 요약 복사 | 조회 기간, 시군별 건수, 주요 월, ‘기타(직접입력)’ 건수, 파일명을 집계값으로 조립한다. 결과가 0건이면 해당 조건과 0건 문구를 복사한다. |
| 후속 | AI 문장 다듬기 | 담당자 수요가 확인되면 검증된 집계값을 전달해 문장을 다듬는다. 화면 수치와 어긋나는 출력에는 기본 요약을 사용한다. 담당자가 내용을 검토하고 회의 자료에 사용한다. |
| 후속 | 기간 비교 및 위치 분석 | 전년 동일 기간 비교는 자료별 수록 범위 확인 후 추가한다. 지도는 행정구역 코드와 경계 자료를 확보한 뒤 검토한다. |

현재 데이터의 활용 범위는 과거 발생 기록 조회와 비교다. 실시간 감시나 예측, 순찰 인력 자동 배치는 별도의 현장 데이터와 운영 검증이 필요한 과제로 둔다.

| 문제 가설 검증 | 인터뷰에서 최근 예방계획 작성 자료, 실제 반복 집계 빈도, 보고 양식, 기존 시스템으로도 충분한지 확인한다. 집계 부담이 작다면 원문 확인과 결과 공유에서 효용이 있는지 살펴보고 기능 우선순위를 조정한다. |

## 6. 구현 인계

교육용 시제품은 **Python과 Streamlit**을 활용해 한 화면 웹앱으로 구성하는 안을 제안한다. 제공 CSV를 읽어 열 구조를 검증하고, 지역명 공백을 정리한 뒤 하나의 필터 결과로 그래프·표·상세·요약을 생성한다. 원본 CSV는 보존하고, 화면에서 파일명과 조회 조건을 함께 보여준다.

### 6.1 프로젝트 폴더 구조

아래 경로는 모두 `산불관리_pjt/`를 기준으로 한다.

| 폴더 | 역할과 저장 대상 |
| --- | --- |
| `.agent/workflows/` | 강사가 배포한 `create-prd`, `generate-tasks`, `process-task-list` 워크플로를 둔다. |
| `docs/` | 문제 카드, 자료 카드, `asis-tobe.md`, 이 서비스 기획서(`SERVICE_PLAN.md`)를 둔다. |
| `tasks/` | 요구사항 문서 `prd-[서비스명].md`와 작업 목록 `tasks-prd-[서비스명].md`를 저장한다. |
| `data/` | 원본 CSV를 보관한다. 앱은 원본을 읽고, 공백 정리와 필터링은 읽은 데이터에 적용한다. |
| `app/` | AI 코딩 에이전트가 생성한 앱 코드와 구동에 필요한 파일을 저장한다. |
| `report/` | 기능 확인 기록, 사용자 의견, 보고서, 발표자료를 저장한다. |

### 6.2 실습 진행 순서

이번 실습에서는 `create-prd`로 기획서를 바탕으로 PRD를 작성하고, `generate-tasks`로 작업 목록을 만든다. 두 문서는 `tasks/`에 저장한다. 이어 `process-task-list`에 따라 작업을 수행하고 `app/`에 구현 파일을 저장한다. 구현은 아래 기준으로 확인하고 결과를 `report/`에 기록한다.

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | CSV 읽기와 집계 기준 확정 | 강원 218건, 기타 172건, 강릉 25건이 재현된다. |
| 2 | 대시보드와 원본 보기 구현 | 두 시군 비교와 원본 확인이 한 화면 흐름에서 동작한다. |
| 3 | 요약 복사와 사용성 검증 | 조회 수치와 동일한 문장을 복사할 수 있고 담당자 피드백으로 다음 범위를 결정한다. |
