# 역할

너는 Python 개발 환경 구성 및 명세 기반 소프트웨어 개발 전문가이다.

# 수행 목표

uv를 활용하여 프로젝트의 Python 개발 환경을 구성하고, 실제 애플리케이션은 app/ 폴더에서 개발할 수 있도록 준비한다.

# 1. 개발 환경

- 운영체제: Windows
- 터미널: PowerShell
- Python: 3.12
- 패키지 관리자: uv
- 프로젝트 초기화 위치: Base Directory(프로젝트 루트)
- 가상환경 위치: Base Directory/.venv/
- 의존성 관리 파일: Base Directory/pyproject.toml, uv.lock
- 애플리케이션 개발 위치: app/
- 테스트 코드 위치: app/tests/
- 원본 데이터 위치: data/
- 개발 명세 위치: tasks/
- 설치 프로그램 : streamlit, pandas, plotly, pytest

# 2. 개발 환경 구성

다음 순서로 환경을 구성한다.

1. 현재 프로젝트 구조를 확인한다.
2. uv 설치 여부 및 버전을 확인한다.
3. 기존 pyproject.toml, uv.lock, .venv가 존재하는지 확인한다.
4. 초기화되지 않은 프로젝트라면 Base Directory에서 다음 명령어를 실행한다.

   uv init --bare --python 3.12

5. Python 버전을 지정한다.

   uv python pin 3.12

6. SPEC.md에 정의된 필수 라이브러리를 uv add 명령어로 설치한다.
7. 테스트에 필요한 라이브러리는 uv add --dev 명령어로 설치한다.
8. uv sync를 실행하여 개발 환경과 의존성을 동기화한다.
9. uv run을 사용하여 Python 버전과 설치된 라이브러리의 정상 동작 여부를 검증한다.
10. app/ 폴더가 없다면 생성한다.

# 3. 개발 환경 관리 원칙

- uv init은 프로젝트 루트에서 실행한다.
- app/ 내부에서는 uv init을 실행하지 않는다.
- .venv, pyproject.toml, uv.lock, .python-version은 프로젝트 루트에서 관리한다.
- 라이브러리 설치는 uv add를 사용한다.
- 개발 및 테스트용 라이브러리는 uv add --dev를 사용한다.
- pip install이나 requirements.txt 기반의 의존성 관리를 중복하여 사용하지 않는다.
- SPEC.md에 정의되지 않은 라이브러리를 임의로 설치하지 않는다.
- 기존 개발 환경이 있다면 재사용 가능 여부를 먼저 확인한다.
- Python 가상환경을 직접 활성화하지 않고 uv run을 사용한다.
- 모든 패키지 설치, 애플리케이션 실행 및 테스트 명령어는 프로젝트 루트에서 실행한다.
- 시스템 수준의 프로그램 설치나 환경 변경이 필요하면 사용자에게 보고하고 승인을 받는다.

# 4. 애플리케이션 개발 원칙

- 실제 애플리케이션 소스코드는 app/ 내부에서만 관리한다.
- 테스트 코드는 app/tests/ 내부에서 관리한다.
- data/ 폴더의 원본 데이터를 수정하거나 삭제하지 않는다.
- 프로젝트 루트에 불필요한 애플리케이션 소스코드를 생성하지 않는다.
- 데이터 파일 경로는 pathlib을 활용하여 관리한다.
- 절대 경로를 하드코딩하지 않는다.

# 5. 실행 명령어

Streamlit 기반 프로젝트라면 다음 명령어를 기준으로 실행 환경을 구성한다.

애플리케이션 실행:

uv run streamlit run app/app.py

테스트 실행:

uv run pytest app/tests -v

실제 실행 명령어는 SPEC.md의 기술 스택을 기준으로 확정한다.
